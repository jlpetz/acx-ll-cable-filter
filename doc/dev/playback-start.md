# Checking a cable's first playback packet

This check detects the short opening that occasionally disappeared when Windows Media Player started a shared 10 ms playback stream. It aligns a seeded stereo marker from its interior, so hundreds of missing opening samples stay visible even when the cable's underrun count is zero.

1. Install NumPy in your Python environment. Run `python tools/playback_start_probe.py make marker.wav`.
2. Choose a spare installed cable with a 48 kHz stereo input/output. In Windows Volume mixer, send **Windows Media Player** to that cable's **In**. Keep player and endpoint gain at 100%, turn enhancements off, and leave the cable's render endpoint free between plays. Pick the output for the player only if you want to preserve your system default.
3. In Audacity pick Windows WASAPI, the cable's **Out** or **Out-5ms** recording device, two channels, and a 48 kHz project. Set export dither to None. Start recording with playthrough off. Record the cable's microphone output directly; an endpoint-loopback recording can keep the render pin warm and change the test.
4. After at least 100 ms of silence, open `marker.wav` in Windows Media Player, let it finish and leave at least another 100 ms of silence. Stop recording. Export the full recording as signed 16-bit PCM WAV. Use a separate recording for each attempt.
5. Run `python tools/playback_start_probe.py check take.wav`. The shared engine can fade in its first 480 frames. The checker reports where consecutive stereo frames begin matching the marker's signs through the fade, including samples only one PCM16 step above zero. It allows two opening frames for rounding and checks the remaining 95,657 stereo frames against the source. A reported onset near 415 or 416 reproduces the characteristic missing opening. Repeat across fresh playback starts when comparing drivers.
6. To check the checker, first paste `marker.wav` between silence guards in a fresh 48 kHz Audacity project, export, and verify it passes. Then silence its first 416 frames using sample selection and **Silence Audio** (preserve their time), export again, and verify it fails with the continuous stereo match starting at frame 416. An ordinary silence gap before a valid clip does not affect the result.

Record the driver version, playback and recording applications, endpoint roles, sample rate, Verifier state, and each checker's output. WPP and a process-loopback reference are needed to attribute a captured gap to a particular component. If using a comparison cable, repeat the identical procedure with its matched playback and recording endpoints.
