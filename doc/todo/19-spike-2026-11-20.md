# 19. The driver spike (started 2026-11-20)

The first spike of doc/todo/19-driver-base-2026-10-28.md ("First spike": seven checks), on its own EC2 box, separated by
the owner from the TMR dev box: **its own EC2 instance** (r8i.2xlarge, a clone of the TMR dev box,
which stays TMR's; same computer name). Windows Server 2025 (26100), UEFI with Secure Boot off.

## Set-up (2026-11-20)
- **Toolchain, on the box already:** Visual Studio Community 2026 18.12 with the WDK extension
  (`WindowsKernelModeDriver10.0` toolset), WDK and SDK 10.0.28000 (WDK 28000.2526). Frameworks on the box:
  Wdf01000.sys 1.35.26100.3323 (KMDF 1.35), Acx01000.sys 10.0.26100.33822 (ACX 1.1; the WDK's headers have 1.0 and 1.1).
  Audiosrv running.
- **KMDF 1.35** (the owner, 2026-11-20: "target the latest KMDF 1.35"): the newest the WDK has and the box runs. It needs
  Windows 11 24H2 or Server 2025 (26100) and up, so the INF's floor is `10.0...26100` and the catalog is made for
  `10_GE_X64,Server2025_X64`. (1.33 would have kept 22H2 and 23H2.)
- **The base:** the ACX AudioCodec sample at Windows-driver-samples d49bb7d (2026-11-05), imported verbatim into
  `driver/src` (a0cccd1; MS-PL), then changed (KMDF 1.35, the INF floor). The unmodified sample builds (64 KB .sys).
- **WDK 28000 under VS 2026:** two post-build checks fail on tooling, not code. The InfVerif task looks for
  `x86\InfVerif.dll` (it's under `build\10.0.28000.0\bin\x64`), and ApiValidator's `aitstatic.exe` exits 193. The build
  turns both off (`SkipPackageVerification`, `ApiValidator_Enable=false`) and runs InfVerif from `Tools\...\x64`: clean.
- **Test signing** (`driver/scripts`, ported from TMR-MD's build.ps1, which worked on Windows 11): a self-signed
  code-signing certificate `CN=Noise Filter Test Driver` in LocalMachine\My,
  trusted in Root and TrustedPublisher; `bcdedit /set testsigning on`. The package (`.sys` and catalog) signs and
  verifies. EMS (for the EC2 serial console, the script's `-Ems`) was turned on, then reverted at the owner's request
  (2026-11-20: as few changes as possible against the baseline): `ems` deleted from `{current}`, `emsport` and
  `emsbaudrate` from `{emssettings}`. Against the TMR box's boot settings (the owner's paste), this box's differ only by
  `testsigning Yes`; `{emssettings} bootems Yes` is AWS's own, on both.
  Git Bash's PSModulePath lists PowerShell 7's modules first, which leaves Windows PowerShell 5.1 without `Cert:`: the
  scripts are started with `env -u PSModulePath powershell -File ...`.
- **Not checkable from here:** the AWS key on the box can't list or make images; the AMI the clone came
  from is the pre-spike snapshot, the owner's to confirm.

## Checks
1. **Passed (2026-11-20):** AudioCodec, unmodified but for KMDF 1.35, installs test-signed with no prompt
   (`Install-Driver.ps1`: devcon made ROOT\MEDIA\0003, status OK) and shows two endpoints, "Speakers (AudioCodec
   Device)" and "Microphone (AudioCodec Device)". Two findings: Windows made both the default devices (all roles), so
   `Set-DefaultAudio.ps1` (IPolicyConfig) put CABLE-B back; and the sample's endpoints run at 44.1 kHz (the mic mono,
   the speakers stereo), so 48 kHz is part of check 3.
2. **Passed (2026-11-20, 469ca28):** with the packet-size constraints (a 2 ms floor, 128-frame RAW and DEFAULT packets),
   IAudioClient3 gave the filter's shared mic path a 3.33 ms low-latency period on our Microphone endpoint (`run --mic
   "Microphone (AudioCodec Device)" --no-exclusive-mic`: "period 3.33 ms, low-latency period, RAW"; the filter takes the
   smallest period that divides its 480-frame block, 160 frames). VB-CABLE offers nothing under 10 ms. The exact
   GetSharedModeEnginePeriod values are still to read (a 128-frame minimum is expected).
